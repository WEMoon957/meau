小菌点餐智能体 API 文档

服务名：小味点餐智能体 · 框架：FastAPI · 默认监听 0.0.0.0:3000（生产由 gunicorn + nginx 前置）

  • 本地开发：http://localhost:3000
  • 生产：由 nginx 反代，建议 https://your-domain.com
接口源码： main/api_server.py · main/cart_api.py

通用约定 #

统一响应结构

所有业务接口均返回如下 JSON 结构（部分接口有扩展字段）：

{
  "code": 200,
  "msg": "success",
  "...": "业务字段"
}

内容类型

请求体与响应体均为 application/json; charset=utf-8。

鉴权机制（会话令牌） #

系统采用 session_id + session_token 双凭证防御 IDOR（越权访问）：

场景session_idsession_token
新建会话 传空字符串 "" 传空字符串 ""，服务端签发新 token 并在响应中返回
已有会话 必传 必传，且必须与服务端记录匹配
购物车 / 重置操作 必传 必传（必须为已存在的会话）
  • token 校验失败返回 401，需重新发起会话
  • 购物车类接口强制 require_existing=True，不允许匿名 / 新会话直接操作

限流策略 #

固定窗口计数限流（多 worker 部署时计数共享 Redis，单 worker 回退进程内）：

接口类别维度阈值窗口
对话 /api/ai/chat每会话30 次60s
对话 /api/ai/chat每 IP60 次60s
购物车 /api/cart/*、/api/dish/resolve每会话10 次60s
购物车 /api/cart/*、/api/dish/resolve每 IP20 次60s
会话操作 /api/ai/reset每会话10 次60s
  • 超限返回 429，带 Retry-After 头
  • 限流器未就绪或 Redis 故障返回 503

并发与背压

  • 单 worker 最大并发 LLM 调用：MAX_CONCURRENT_CHATS（默认 20）
  • 达到上限立即返回 503（不排队），带 Retry-After: 5

错误码 #

code / HTTP含义触发场景
200成功正常响应
400参数错误session_id 缺失 / 格式非法
401鉴权失败session_token 缺失或不匹配
429限流 / 会话繁忙超阈值或上一条消息仍在处理
500服务内部错误未分类异常
502上游模型异常AgentError / CartAgentError
503服务不可用限流器 / Redis 故障、并发满载、LLM 上游异常

POST /api/ai/chat #

发送用户消息，返回 AI 回复（推荐 / 问答 / 知识库查询统一入口）。

请求体

字段类型必填约束说明
user_messagestring是1–2000 字符用户输入
session_idstring否≤64 字符空 = 新建会话
session_tokenstring否≤128 字符空 = 新建会话
membership_levelstring否≤32 字符，默认"普通会员"会员等级

响应

字段类型说明
codeint200
msgstring"success"
aimessagestringAI 回复文本（已剥离 DSML / 控制字符）
session_idstring会话 ID（新会话为新生成的 UUID）
session_tokenstring新会话非空（需前端保存），已有会话为空字符串

示例

// 请求（新建会话）
{
  "user_message": "6个人吃，要特辣",
  "session_id": "",
  "session_token": ""
}

// 响应
{
  "code": 200,
  "msg": "success",
  "aimessage": "为您推荐：\n1. 菌汤生态鸡子母锅(￥128)...\n合计：￥xxx",
  "session_id": "a1b2c3d4-...",
  "session_token": "eyJhbGciOi..."
}

  "code": 200,
  "msg": "ok",
  "data": {
    "dish_count": 120,
    "active_sessions": 5,
    "max_sessions": 1000,
    "session_ttl_seconds": 1800,
    "max_concurrent_chats": 20,

字段类型必填说明

session_idstring是已存在会话
session_tokenstring是会话令牌

响应

shopIdstring否""-
brandIdint否0-

session_idstring是-会话鉴权
session_tokenstring是-会话鉴权

POST /api/cart/agent-chat #

用户用自然语言说要加什么菜（如 "来份菌汤生态鸡子母锅和两份单点绣球菌加购"），由 CartAgent 用 LLM 提取菜名 → 反查 id → 同步批量加购 → 自然语言回复。与对话接口平行，前端按意图路由。

请求体

字段类型必填约束说明
user_messagestring是1–500 字符自然语言加购指令
session_idstring是1–64 字符已存在会话
session_tokenstring是1–128 字符会话令牌

响应

{
  "code": 200,
  "msg": "success",
  "aimessage": "已为您加入购物车：\n菌汤生态鸡子母锅\n共 1 道已加入购物车~",
  "cart_result": {
    "success_count": 1,
    "failed_count": 0,
    "mocked": true,
    "results": [
      { "goodsId": 12, "goodsName": "菌汤生态鸡子母锅", "ok": true, "msg": "mocked" }
    ]
  },
  "session_id": "a1b2c3d4-..."
}
cart_result 说明：空 null 时表示未识别到要加购的菜品；含 missing 字段时表示部分菜名未在菜单找到

附录 B：业务约束 #

节选自项目硬约束：

  • 每次输入仅返回一个推荐方案
  • 火锅场景必含一个锅底且计入总数
  • 推荐输出含：菜名 + 价格 (+ 辣度 / 招牌) → 合计 → 推荐理由
  • 所有 DB 查询走参数化 + LIMIT + MAX_EXECUTION_TIME(5000) 优化器提示
  • LLM 调用受 LLM_REQUEST_TIMEOUT（默认 30s）约束
  • 多 worker 部署必须配置 REDIS_URL，否则拒绝启动
